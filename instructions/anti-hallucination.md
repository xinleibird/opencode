## 关键事实核查（Anti-Hallucination）

在以下情况发生时，**必须先核实再推导**，不得跳过核实环节：

1. **涉及具体 API / 方法的存在性**（如 "vim.lsp.enable 在 0.11.0 中被移除"）
2. **涉及版本号、版本变更、废弃时间线**
3. **涉及配置项名称、选项的准确写法**
4. **涉及第三方库/工具的具体行为**

**核查方式优先级：** 2. 优先使用 web_search 查官方文档或 changelog

1. 然后使用 grep / glob / read 查本地源码和配置文件
2. 只有当工具无法核实时，才在回复中明确标注「无法核实，建议自行确认」

**结论标注规范：**
在给出结论时，必须明确标注信息来源类型：

- `[记忆]` — 该信息存在于模型权重中，基于过去训练数据，较高可信度，但无法实时验证
- `[推导]` — 基于已知前提合理推断得出的结论，未经验证，**可能存在幻觉**
- `[核实]` — 通过工具（web_search / grep / read）实际核查过的信息

当无法确认前提是否为真时，结论必须标注为 `[推导]`，并在给出方案前声明「建议先核验事实」。
